# 执行精华 · 离线/受限现场 服务接口对接联调

Date: 2026-06
Provenance: 一次企业级 SOC 系统的客户现场离线联调（arm64 离线包、无外网、环境改不动、求人成本高）。已脱敏——不含任何客户/厂商/地址/库名/凭据信息。

- **problem_domain**: 跨机、跨架构、带安全模式、改不动的客户现场，做服务接口对接联调。
- **solution_summary**: 一套「自助脚本化 + 分层探针」的排障元策略 + 5 个高频陷阱（每个含 现象/根因/教训/样例）。
- **applicable_scenario**: 离线 / 内网 / arm64 / kerberos 安全集群 / 第三方厂商客户端对接。纯应用层代码联调不适用——这些专属于"环境受限 + 跨架构 + 厂商定制件"的现场。

---

## 0. 元策略：受限现场，把「求人」换成「自助脚本」

现场环境调不动、要四处找人 → **凡能脚本化自助验证的全做成脚本，尽量不动后端代码**。
分层探针，每层一个脚本、自带白话判读：

```
体检(全景) → 库连通 → 接口对接 → 任意地址即时测
```

排障第一刀永远是「体检」，然后顺依赖链从上游往下走。

## 1. 表象容器 vs 根因容器（compose 依赖链）

- **现象**：网关 / 前置容器起不来、「没有 port」。
- **根因**：它 `depends_on: {上游: service_healthy}`，上游没 healthy 就根本不被创建。
- **教训**：下游没起，**先查上游 health，别在表象容器上耗**。
- **样例**：`docker compose ps` 看谁 unhealthy → `docker compose logs --tail=80 <上游>`。

## 2. 本地能连 ≠ 远程能连（回环陷阱）

- **现象**：DB 客户端本机能连，部署在另一台机的服务连不上。
- **根因**：本机客户端多半走 `localhost` = 回环，绕过了所有远程限制，**证明不了远程可达**。
- **远程访问三道墙**：① `bind-address` 只绑 127.0.0.1　② 账号是 `@localhost`（需 `@%`）　③ 防火墙挡端口。
- **验证法**：本机客户端改用「本机 IP（非 localhost）」连 —— 连不上即坐实远程没开。

## 3. 配置的「真实来源」陷阱（改对了地方才生效）

- **现象**：改了 `.env` 里的服务地址，完全不生效。
- **根因**：**某些客户端在特定模式下根本不读 env**。例：安全 / 认证模式下，客户端从自己的 `xxxParams.properties` 读地址 + 认证，env 里那个地址是死的。
- **教训**：改配置前先确认「**这个客户端到底从哪读这个值**」。同一个值可能有多个声称的来源，只有一个是真的；模式切换（none ↔ 安全模式）经常会换掉真实来源。
- **认知钩子**：这是「单一事实源」的反面教材 —— 配置散在多处、真实来源不显式，就会改错地方耗一整天。

## 4. 只读挂载 vs 运行时写

- **现象**：容器报「某文件不能删除 / 写不了」，客户端起不来。
- **根因**：配置目录挂成 `:ro`，但第三方客户端运行时要在该目录**动态生成 / 删除**临时文件（如认证 JAAS）。
- **教训**：第三方客户端可能在配置目录写运行时文件；**报写 / 删失败先查挂载模式**。解：去掉 `:ro`（必要时放宽目录权限）。

## 5. 跨架构 native 兼容（离线部署头号雷）

- **现象**：arm64 机上，厂商 jar 起客户端报 `UnsatisfiedLinkError`。
- **根因**：厂商 jar 内的 native（`.so` / JNA）往往只带 x86。
- **定位法（别急着搬料）**：先抓确切报错分类——
  ```
  logs | grep -iE "native|UnsatisfiedLink|os.arch|jna|libjnidispatch|x86|aarch"
  ```
  - 通用依赖（如 JNA）：本地依赖多半已自带 aarch64 版 → **本机换依赖重打包即可，现场无需带任何东西**。
  - 厂商私有 `.so`：才需要厂商的 arm64 版那个件，install 替换后重打。
- **教训**：离线 / 跨架构部署，**先把 native 报错分类成「通用 vs 厂商私有」**，再决定要不要劳师动众。

## 适用边界

这些专属于「跨机、跨架构、带安全模式、改不动环境」的现场对接，与具体厂商无关。纯应用层代码联调不会撞到它们 —— 别把它们当通用 web 调试经验套。

# 结构化表达 · L3 调度规则

> 迁自 kg `index/topics/structured-expression.yaml` `L3_dispatch_rules`（2026-08-12 跨仓迁移波，
> 批 2 片 4 乙-6 判决"整段是可执行 skill 规格 → cg skill；topic 留判断 + 一句调度规则住哪"）。
> 判断层正本（表达主线/骨架嵌套/受众匹配等 insight）与方法论清单（L1 学术验证 / L2 实践框架）仍在 kg 该 topic。

## 1. 按内容目标匹配方法论（主维度）

| 目标 | 方法论 |
|:--|:--|
| 展示成果/业绩 | star-r, prep |
| 说明背景/引出问题 | scqa, 5w2h, 3s |
| 提出问题/风险上报 | 3s, risk-four-steps |
| 给方案/说服人 | ride, fabe, grow |
| 讲计划/规划 | grow, 5w2h |
| 讲解原理/教概念 | pyramid-principle, fabe, 5w2h |
| 总结/重申观点 | prep, pyramid-principle |
| 技术方案讲解 | wsr, fabe |
| 资源申请/预算审批 | ride, prep, scqa |
| 对齐目标/进度同步 | grow, 3s |

## 2. 按受众类型调整表达方式（辅维度）

| 受众 | 适配 |
|:--|:--|
| decision_maker | 结论前置、数据量化、给选择题、控制细节量 |
| learner | 框架先行、用类比、渐进展开细节、留深入路径 |
| collaborator | 意图先行、明确分工和时间线、预留讨论空间 |
| general_audience | 关联性先行、控制专业术语、故事化案例 |

## 3. 单个信息单元的标准化生产流程

1. **定唯一目标**：这个单元只解决一个问题
2. **识别受众**：决策者/学习者/协作者/通用
3. **选方法论**：按 unit_goal + audience_type 匹配逻辑骨架（上两表）
4. **嵌套内容**：把素材填进骨架
5. **精简强化**：只保留服务目标的信息，按受众偏好调整详略

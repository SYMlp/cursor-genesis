# State Header Contract v1

> contract_version: 1.1 · 2026-08-17（1.0 同日发布，见文末版本说明）
> 类型：机器可验证契约（Machine Enforced 档）
> 消费方式：init/build 注入或直接引用；验证器见 `scripts/validate_state_header.py`

## 契约内容

任何登记进驾驶舱/看板类聚合器的项目真相源文件（`PROJECT-STATE.md` / `PROGRESS.md` 等），**文件最顶部**必须放一个 front-matter 机器头：

```markdown
---
project: <项目名>
status: 🟢            # 🟢顺畅 / 🟡有卡点 / 🔴阻塞 / ⚪暂停
ball: me              # me=球在你半场（能现在动）/ them:<谁>=在等谁
next: <一句话下一步>
updated: <YYYY-MM-DD>
---
```

### 字段规范

| 字段 | 必填 | 格式 |
|:---|:---|:---|
| `project` | 是 | 非空字符串 |
| `ball` | 是 | `me` 或 `them:<谁>`（首个冒号后为等待对象） |
| `next` | 是 | 非空一句话 |
| `updated` | 是 | ISO 日期 `YYYY-MM-DD` |
| `status` | 否（v1.1 起） | 若存在，以 🟢 / 🟡 / 🔴 / ⚪ 之一开头 |
| `stale_after` | 否 | 整数天数，覆盖该文件的默认过期阈值 |

**字段分工原则（v1.1）**：机器头只硬性承载**机器观测不到的判断态**——球在谁半场（`ball`）、下一步是什么（`next`）、这个判断多久没人复核（`updated`）。服务活没活、端口通不通、容器状态等**机器可观测事实归动态探针**，不该人肉喂进头里——人肉标注的可观测状态过期后会双向说谎（活的标死、死的标活）。`status` 保留为可选的人工总评位。

未列出的额外字段允许存在（开放扩展），解析器必须忽略而非报错。

### 解析规则

1. 头以文件第一行 `---` 开始、下一个 `---` 结束；聚合器只读头、不碰正文。
2. 每行按**第一个冒号**切 key/value（`ball: them:张三` 的值必须保得住）。
3. 容忍 UTF-8 BOM（Windows 旧文件常见）。

## 裁判语义（死存根裁判）

聚合器对每个登记项目按以下顺序判级，**后置兜底、不靠"顺手改头"的自觉**：

| 级别 | 条件 | 语义 |
|:---|:---|:---|
| `critical` | 文件读不到 / 无头 / 必填字段缺失 / `updated` 非 ISO 日期 | 死存根。登记了就不许静默消失——静默消失=驾驶舱失明，比过期更红 |
| `stale` | `今天 - updated` > 阈值（默认 **7 天**，可被 `stale_after` 覆盖） | 头没人喂了，状态不可信 |
| `ok` | 以上都不是 | 头可信，可参与"球在谁半场"分组 |

`critical` 严格重于 `stale`：格式坏掉的头比过期的头更危险，因为它让人误以为"有登记就有监控"。

## 登记表格式（可选配套）

聚合器侧维护一份登记表，声明哪些真相源喂进来：

```json
{
  "projects": [
    { "name": "<显示名>", "harness": "<真相源文件绝对或相对路径>" }
  ]
}
```

验证器支持 `--registry <登记表.json>` 批量横扫。

## 设计依据

- **为什么是后置裁判不是前置纪律**：前置规则（"必须及时更新头"）吃 attention 且必被偶发违反；机器裁判不吃 attention，违反时亮红即可。契约把人的义务压缩到 5 行填空，把监督交给代码。
- **为什么头坏比过期更红**：过期是"信息旧了"，头坏是"监控通道断了还没人知道"——后者破坏的是整个聚合机制的可信度。
- **作用域主语**：本契约管的是"一个人全部项目的球权与鲜活度"，作用域主语是使用者的体系而非任何单一 harness 产品——这正是它值得进 CG 货架的判据（harness 厂商不会替你管跨仓球权）。
- **裁判裁的是判断鲜活度，不是服务鲜活度**（v1.1 收窄）：`updated` 过期意味着"没人复核过这个判断"，不意味着"服务挂了"——后者由探针实时回答。

## 版本说明

- **1.1**（2026-08-17）：`status` 由必填降为可选。触发：消费方实测发现人工 status 双向失真（真事故已修但头仍报 502 幽灵事故；7/7 登记项目头过期），拍板"机器可观测态归探针、判断态归头"。v1.0 头在 v1.1 下全部有效（纯放宽，无破坏性变更）。
- **1.0**（2026-08-17）：首发，5 字段全必填 + 死存根裁判语义。

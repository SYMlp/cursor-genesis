# 验证实例：安全管理中心 (security-mgmt-center)

> 验证日期：2026-03-14
> 系统定位：等保二级安全管理中心
> 原型识别：**收集型**（主）——从多种安全设备和系统收集安全资产、日志、告警，统一管理

## 一、原型识别过程

### 系统一句话

"从多种安全设备和外部系统收集安全资产信息，在统一平台上进行资产纳管、态势感知和安全事务处理。"

### 识别信号匹配

| 信号 | 匹配情况 |
|:---|:---|
| 从多个外部来源获取数据 | ✅ 天融信防火墙、深信服 WAF、安恒堡垒机等 |
| 数据进入后需去重规范化 | ✅ 资产按 IP+端口去重 |
| 追踪每条数据的来源 | ✅ 资产探测/同步/手动录入 |
| 数据有暂存→确认的生命周期 | ✅ 临时资产→正式资产→归档资产 |

## 二、通用模式验证（五域）

安管系统包含五个主要子域：资产 (asset)、知识 (knowledge)、态势 (posture)、事务 (affairs)、审计 (audit)。

### 模式 1：来源追溯三件套

| 域 | 被收集实体 | sourceType 值 | sourceRef 指向 |
|:---|:---|:---|:---|
| 资产 | SecurityAsset | 资产探测 / 资产同步 / 人工录入 | 发现任务 / 同步任务 |
| 知识 | 漏洞知识 | 接收任务 / 人工录入 / 外部推送 | 接收任务 |
| 态势 | 告警 | 分析模型生成 / 外部推送 / 人工 | 分析模型 / 外部接口 |
| 事务 | 案事件 | 告警升级 / 人工创建 / 外部通报 | 源告警 / 通报 |
| 审计 | 审计日志 | 系统采集 / 设备上报 | 采集配置 / 设备 |

**结论**：五域全部适用。三件套是收集型系统的通用基础设施。

### 模式 2：去重机制

| 域 | uniqueKey | 去重策略 |
|:---|:---|:---|
| 资产 | IP + 端口 (或应用标识) | 合并（取字段并集） |
| 知识 | 知识标识符 (CVE ID 等) | 版本化（保留历史） |
| 审计 | 设备 + 时间戳 + 事件类型 | 丢弃后来者 |

### 模式 3：冲突校验

| 场景 | 冲突处理 |
|:---|:---|
| 手动修正 vs 扫描更新 | 手动修正优先（权威度高） |
| 不同设备报告同一资产不同属性 | 按设备权威度排序 |

### 模式 4：生命周期管理

| 阶段 | 安管实现 | 专属属性 |
|:---|:---|:---|
| temporary | 临时资产（发现/同步进入） | sourceParty, discoveredBy, sourceType |
| active (onboarded) | 正式资产（人工确认后） | credential, identity registration |
| archived | 归档资产（停用后） | archivedAt, archiveReason |

### 模式 5：任务管理

| 任务类型 | 对应域 | 调度方式 |
|:---|:---|:---|
| 资产发现任务 | 资产 | 周期性 + 手动 |
| 知识同步任务 | 知识 | 周期性 |
| 日志采集配置 | 审计 | 事件触发（设备上报） |

### 模式 6：通道适配层

| 通道 | 适配器 | 协议 |
|:---|:---|:---|
| 天融信防火墙 | TianrongxinFWAdapter | HTTP API |
| 深信服 WAF | SangforWafAdapter | HTTP API |
| 安恒堡垒机 | AnhengFortressAdapter | HTTP API |
| 手动录入 | (前端直接提交) | — |

### 模式 7：数据质量审计

| 检查类型 | 安管实现 |
|:---|:---|
| 完整性 | 资产必填字段校验（assetName, mainType） |
| 格式 | IP 地址格式校验、端口范围校验 |
| 一致性 | mainType 与 applicableTo 属性匹配 |

## 三、实体推导验证

### SecurityAsset 的维度推导

**维度 A（生命周期）**：

| 阶段 | 推导出的属性 | 实际实现 | 命中 |
|:---|:---|:---|:---|
| temporary | sourceParty, sourceType, discoveredBy | ✅ 全部实现 | ✅ |
| onboarded | credential, identityRegistration | ✅ 全部实现 | ✅ |
| archived | archivedAt, archiveReason | ✅ 全部实现 | ✅ |

**维度 B（主类型）**：

| 主类型 | 推导出的属性 | 实际实现 | 命中 |
|:---|:---|:---|:---|
| IP 资产 | ipAddress, macAddress, osType | ✅ applicableTo 机制 | ✅ |
| 应用资产 | accessUrl, belongPlatform | ✅ applicableTo 机制 | ✅ |
| 数据资产 | dataLevel, storageLocation | ✅ applicableTo 机制 | ✅ |

## 五、收获

1. 安管的五个子域全部匹配收集型通用模式，验证了原型的跨子域通用性
2. 实体推导（生命周期×主类型）的结果与已有实现高度吻合，验证了推导方法的有效性
3. 已有的 `applicableTo` 机制就是"主类型维度属性涌现"的工程实现——实践先于理论命名
4. 冲突校验和异常检测是审计发现的缺口——可作为后续迭代方向

# 收集型系统：缺口审计检查表

> 使用方式：对照通用模式逐条检查，标注 ✅ 已有 / △ 部分有 / ✗ 缺失
> 配合五步法 Step 3 使用

## 使用说明

1. 先完成 Step 1（原型识别）和 Step 2（通用模式对照），确认系统确实是收集型
2. 对下表每一行，在"当前状态"列填写对应物（或标注缺失）
3. 缺失项 = 系统隐含需要但尚未实现的能力
4. 完成后交给 PM 审核 delta（Step 5）——哪些缺失项需要补，哪些对本项目不适用

## 审计表

### 模式 1：来源追溯三件套

| 检查项 | 问题 | 当前状态 |
|:---|:---|:---|
| sourceType 字段 | 系统是否记录了每条数据的来源通道类型？ | |
| sourceRef 字段 | 是否能追溯到具体的采集任务/同步通道/外部接口？ | |
| operator 字段 | 是否记录了操作人（人工操作）或系统标识（自动操作）？ | |
| 与技术审计区分 | 业务来源字段是否独立于 create_by/update_by？ | |

### 模式 2：去重机制

| 检查项 | 问题 | 当前状态 |
|:---|:---|:---|
| 业务唯一标识 | 每种实体是否定义了业务级 uniqueKey（不是数据库主键）？ | |
| 去重策略 | 发现重复时的处理策略是什么？（丢弃/合并/版本化） | |
| 去重范围 | 去重是全局的还是按来源/时间窗口？ | |
| 去重时机 | 在数据入库前去重还是入库后定期清理？ | |

### 模式 3：冲突校验

| 检查项 | 问题 | 当前状态 |
|:---|:---|:---|
| 来源权威度 | 是否定义了不同来源的可信度排序？ | |
| 冲突字段识别 | 是否明确了哪些字段可能出现来源间不一致？ | |
| 处理策略 | 冲突时自动覆盖 / 保留双方 / 人工裁决？ | |

### 模式 4：生命周期管理

| 检查项 | 问题 | 当前状态 |
|:---|:---|:---|
| 阶段定义 | 实体有明确的生命周期阶段（暂存→正式→归档）？ | |
| 阶段转换规则 | 每个转换是否有前置条件？ | |
| 阶段专属操作 | 不同阶段允许的操作是否不同？ | |
| 阶段专属属性 | 是否识别了每个阶段的专属字段？（见视角依赖属性涌现） | |

### 模式 5：任务管理

| 检查项 | 问题 | 当前状态 |
|:---|:---|:---|
| 任务定义 | 采集/同步操作是否通过任务对象承载？ | |
| 任务调度 | 是否支持周期性/事件触发/手动三种调度？ | |
| 任务监控 | 是否有成功率、耗时、异常的监控？ | |
| 任务结果统计 | 是否记录每次任务的采集/新增/去重/失败数量？ | |

### 模式 6：通道适配层

| 检查项 | 问题 | 当前状态 |
|:---|:---|:---|
| 统一接口 | 是否有统一的采集/同步接口抽象？ | |
| 适配器注册 | 已接入的通道是否有注册表可查？ | |
| 连接配置 | 每个通道的配置（地址/认证/格式）是否结构化管理？ | |
| 数据规范化 | 不同来源的数据是否统一为内部格式？ | |

### 模式 7：数据质量审计

| 检查项 | 问题 | 当前状态 |
|:---|:---|:---|
| 完整性检查 | 必填字段缺失时是否有处理？ | |
| 格式校验 | 字段格式（IP/日期/枚举等）是否有校验？ | |
| 一致性检查 | 字段间逻辑是否一致？ | |
| 异常检测 | 是否有数量/频率等维度的异常告警？ | |

```markdown
### 覆盖统计

- △ 部分：X / 7 个模式
- ✗ 缺失：X / 7 个模式

### 关键缺口
1. [缺口描述] → 影响：[影响分析] → 建议优先级：高/中/低
2. ...

### PM 审核意见
- 以下缺口需要补：...
- 以下缺口本项目不适用：...（说明理由）
```
